# Contributing

Check the target repository's own guidance first. Repository-specific rules
override these organization defaults.

Before opening a change:

1. Discuss substantial or breaking work with the maintainers.
2. Keep the change focused and preserve existing contracts unless a migration
   is agreed.
3. Add or update tests for changed behaviour.
4. Run the repository's documented formatting, lint, test, and build checks.
5. Update contracts and documentation in the same change.
6. Describe security, compatibility, rollout, and rollback implications.

Never include credentials, customer data, private source, or generated secrets.
AI-assisted contributions remain the contributor's responsibility and require
the same review and evidence as other changes.
